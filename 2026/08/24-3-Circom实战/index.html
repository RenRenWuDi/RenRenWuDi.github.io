Circom实战：写出你的第一个ZK电路

编译、生成证明、验证的完整流程

1. 在 ZK 里，”计算”长什么样

进入实战前要先扭转一个观念：ZK 里的”程序”不是普通代码，而是一个算术电路——一组约束方程。证明者要证明的是”我知道一组输入，让这些方程都成立”。电路不”运行”出结果，而是”声明”一组等式必须成立。这个区别是新手最容易卡住的地方：你不是在写 if-else 算答案，而是在写”什么关系必须为真”。

举个例子。我们想证明”我知道一个数 x，它的平方公开输出是 out，但我不告诉你 x”。在电路里，这不是写一句 out = x*x 然后 print，而是声明一条约束 out <== x * x，并标记 x 是私有输入、out 是公开输出。证明者提供 x 的具体值（叫 witness，见证），验证者只看到 out 和最终的证明，永远不知道 x。

电路的本质：

不是”运行程序”，而是”声明一组等式必须成立”。
证明者提供私有的 witness（见证值），验证者只看到公开输入和最终的证明。

2. 第一个电路：证明知道平方根

下面这个 Circom 电路，声明了”私有输入 x 的平方等于公开输出 out”。注意三个关键字：signal input 是输入信号，signal output 是输出信号，<== 是”约束赋值”——它既把右边的值赋给左边，又向电路添加一条”左边必须等于右边”的约束。这套约束会被编译成 R1CS（秩一约束系统），成为后面生成证明的数学对象。

3. 编译：从电路到约束系统

用 circom 命令把 .circom 文件编译，生成两份关键产物。第一份是 .r1cs 文件，它描述了约束系统——也就是”有哪些等式必须成立”。第二份是 wasm 计算文件，它能在给定输入时，把所有中间信号的值算出来，生成 witness（见证）。这两个产物分工明确：r1cs 定义”规则”，wasm 负责”填值”。

编译后你要准备一个输入文件，写上 x 的具体值（比如 7）。然后运行 wasm，它会执行电路、算出 out=49，并把所有信号的值写入 witness.wtns。这个 .wtns 文件就是”我知道 x=7 让 out=49”的私密证据——它留在证明者机器上，绝不外传。

4. 可信设置与生成证明

证明系统需要一个公共参数才能工作，这个参数通过”可信设置”生成。以 PLONK 为例，它用通用设置（一次生成、多电路复用）。snarkjs 的 plonk setup 把 r1cs 和公共参数（.ptau 文件）合成为证明密钥（.zkey）。然后 plonk prove 用 witness 和证明密钥，算出最终的 proof.json 和 public.json。

这里有个关键的安全属性：proof.json 是那条证明串，public.json 是公开输出（本例是 out=49）。验证者拿这两个文件就能确认”确实有人知道 x 使 x²=49”，却始终不知道 x=7。整个过程中，私有输入 x 从未离开证明者机器——这是 ZK 的底线，也是它价值所在。

5. 验证：无需知道 x

验证是整条链路里最轻的一步。验证者拿到验证密钥、公开输出 public.json 和证明 proof.json，运行 plonk verify，得到 OK 即代表证明有效。注意验证者手上只有 out=49 和一条证明，他既没有 x，也不需要 x——这正是 ZK 的意义。在链上场景，验证密钥会被编译成合约里的验证函数，任何人都可以在链上用极小成本校验这条证明。

完整链路：

circom 写电路 → 编译出 R1CS+wasm → 算 witness → 可信设置 → 生成 proof → 验证

全过程中，私有输入 x 从未离开证明者机器。
